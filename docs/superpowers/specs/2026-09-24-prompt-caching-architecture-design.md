# Архитектурная спецификация: Оптимизация Prompt Caching по стандартам DeepSeek Harness

- **Дата:** 24 сентября 2026 г.
- **Статус:** Утверждён к реализации
- **Целевая система:** `dnd-ai-master` (`C:\antig\battle+ai`)
- **Цель:** Достижение 95–97% Cache Hit Rate для LLM-запросов (DeepSeek-V3 / DeepSeek-R1 / Polza.ai), сокращение расходов на API в 10–30 раз и ускорение времени ответа (TTFT).

---

## 1. Контекст и проблема

### 1.1. Механика работы KV-кэша DeepSeek (Prefix Caching)
- DeepSeek кэширует контекст блоками по 64 токена, начиная строго с **токена 0 (самое начало запроса)**.
- Пока префикс запроса байт-в-байт совпадает с предыдущим запросом сессии, токены считываются из памяти GPU без повторных вычислений.
- **Экономика Polza.ai / DeepSeek:**
  - Токены из кэша (`cacheReadTokens`): **0.49 ₽ / 1M токенов**.
  - Токены мимо кэша (`inputTokens`): **16.47 ₽ / 1M токенов** (разница в **33 раза**!).
- **Цена изменения в префиксе:** если хотя бы 1 токен изменился в начале запроса (в системном промпте на токене ~150), дерево KV-кэша ветвится, и **все последующие 20 000+ токенов истории диалога оплачиваются по полной цене (100% Cache Miss)**.

### 1.2. Диагностика текущего состояния `dnd-ai-master` (Cache Hit ~0%)
1. **Динамический системный промпт:** В `src/app/api/chat/route.ts` в `instructions` на каждом раунде добавляется `buildSceneContext()`. Этот блок содержит:
   - Текущие HP героев (`c.hpCurrent/c.hpMax`), меняющиеся каждый раунд.
   - Качественные статусы NPC («ранен», «без сознания»).
   - 6 последних событий (`gameEvent`), отсортированных `createdAt: "desc"` (новое событие встаёт первым, сдвигая весь текст).
   - В результате нулевой блок токенов мутирует на 100% при каждом ходе.
2. **Скользящее окно FIFO `slice(-VERBATIM_MESSAGES)`:**
   - При превышении лимита (10 сообщений) из начала выпадает 1 старое сообщение. Смещение токенов сдвигается, что гарантирует 0% кэша на каждом последующем ходе.

## 2. Архитектура: Модульная 3-зонная модель контекста

Система организует контекст каждого запроса в 3 строго изолированные зоны в модуле `src/lib/ai/caching/`:

```
┌──────────────────────────────────────────────────────────────────────────────────┐
│ ЗОНА 1: FROZEN PREFIX (Замороженный системный промпт и инструменты)              │
│ • Файл: src/lib/ai/caching/frozen-prefix.ts                                      │
│ • Содержимое:                                                                    │
│   - DM Persona (стиль, тон, строгость правил D&D 5e)                             │
│   - Лор кампании, описание мира, цели текущего Акта сюжета                       │
│   - Статичные досье героев партии (раса, класс, черты характера, идеалы)         │
│   - Детерминированные алфавитно отсортированные схемы инструментов (Tools)      │
│ • Свойство: 100% побайтовое совпадение на протяжении всей кампании.               │
│ • Кэш: 100% Cache Hit с раунда 2 и далее.                                        │
├──────────────────────────────────────────────────────────────────────────────────┤
│ ЗОНА 2: APPEND-ONLY MESSAGE STREAM (Монотонная история диалога)                  │
│ • Файл: src/lib/ai/caching/milestone-compactor.ts                                │
│ • Содержимое:                                                                    │
│   - [Раунд 1] User -> Assistant                                                  │
│   - [Раунд 2] User -> Assistant                                                  │
│   - ...                                                                          │
│   - [Раунд N-1] User -> Assistant                                                │
│ • Свойство: Сообщения строго дописываются в конец. Ни одно сообщение прошлого не │
│   сдвигается и не выпадает по одному.                                            │
│ • Кэш: 97–99% Cache Hit от хода к ходу.                                          │
├──────────────────────────────────────────────────────────────────────────────────┤
│ ЗОНА 3: EPHEMERAL TURN TAIL (Динамический срез обстановки текущего раунда)       │
│ • Файл: src/lib/ai/caching/ephemeral-tail.ts                                     │
│ • Содержимое:                                                                    │
│   - Текущие HP/хиты и временные HP героев                                        │
│   - Состояния и травмы врагов/NPC                                                │
│   - Последние игровые события и броски кубиков сцены                             │
│ • Место вставки: Строго в конец последнего пользовательского сообщения!          │
│ • Свойство: Это единственные свежие токены раунда (~150-250 токенов).            │
│   Оплата без кэша списывается ТОЛЬКО за них.                                     │
└──────────────────────────────────────────────────────────────────────────────────┘
```

## 3. Компоненты и интерфейсы

### 3.1. `src/lib/ai/caching/frozen-prefix.ts`
- Функция `buildFrozenSystemPrompt(campaign: CampaignContext): string`:
  - Собирает неизменяемый системный промпт без единого динамического показателя (без HP, без статусов ранений, без списка свежих событий).
  - Формирует паспорт кампании и статические профили участников.
- Функция `getDeterministicTools<T extends Record<string, any>>(tools: T): T`:
  - Сортирует ключи объекта инструментов в лексикографическом порядке для предотвращения перетасовки схемы JSON при сериализации.

### 3.2. `src/lib/ai/caching/ephemeral-tail.ts`
- Интерфейс `EphemeralSceneState`:
  ```ts
  export interface EphemeralSceneState {
    roundNumber?: number;
    partyStatus: Array<{
      name: string;
      hpCurrent: number;
      hpMax: number;
      hpTemp?: number;
      ac?: number;
      location?: string;
      condition?: string;
    }>;
    npcStatus: Array<{
      name: string;
      healthCondition: string;
      relation: string;
      location?: string;
    }>;
    recentEvents: Array<{
      description: string;
      turn?: number;
    }>;
  }
  ```
- Функция `buildEphemeralSceneTail(campaignId: string, roundNumber?: number): Promise<string>`:
  - Запрашивает из БД свежие данные и формирует блок:
    ```markdown
    [ОБСТАНОВКА И СТАТУС СЦЕНЫ (Раунд N)]:
    - Отряд: Торгрим (HP 24/24, AC 18), Лира (HP 12/16, ранена, AC 13)
    - NPC/Враги: Гоблин-часовой [тяжело ранен], Вожак [здоров]
    - Последние события: Входная решётка захлопнулась; Торгрим зажёг факел
    ```
- Функция `injectEphemeralTailToLastUserMessage(messages: ModelMessage[], ephemeralTail: string): ModelMessage[]`:
  - Клонирует массив сообщений, находит последнее сообщение с `role: "user"` и дописывает блок в его конец:
    `${originalUserText}\n\n${ephemeralTail}`.
  - Все предыдущие сообщения $0 \dots N-1$ остаются побайтово идентичными предыдущему раунду.

### 3.3. `src/lib/ai/caching/milestone-compactor.ts`
- Константы:
  - `MAX_VERBATIM_HISTORY = 30` (порог удержания точных сообщений).
  - `COMPACT_CHUNK_SIZE = 18` (размер сжимаемого блока вехи).
- Функция `compactHistoryWithMilestones(messages: ModelMessage[], campaignId: string): Promise<ModelMessage[]>`:
  - Если `messages.length <= MAX_VERBATIM_HISTORY`: возвращает массив сообщений без изменений (Append-Only).
  - Если `messages.length > MAX_VERBATIM_HISTORY`:
    - Извлекает первые `COMPACT_CHUNK_SIZE` сообщений.
    - Сворачивает их в 1 системное сообщение-веху:
      `[ХРОНИКА РАННИХ СОБЫТИЙ (Раунды 1–X): краткая сводка ключевых фактов...]`.
    - Объединяет: `[MilestoneMessage, ...messages.slice(COMPACT_CHUNK_SIZE)]`.
  - Таким образом, инвалидация кэша происходит ровно один раз на 20-30 раундов игры, а не на каждом ходе.
