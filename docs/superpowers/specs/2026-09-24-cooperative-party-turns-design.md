# Спецификация: Система совместного пошагового хода отряда (Cooperative Party Turns)

**Дата:** 24 сентября 2026 г.  
**Статус:** Утверждено (Approved)  
**Область:** Сетевая игра D&D 5e / AI Dungeon Master (`C:\antig\battle+ai`)  

---

## 1. Контекст и проблема

В текущей версии сетевого стола игроки могут подключиться к одной комнате, однако ввод действий в чат происходил индивидуально — любой игрок мог без ограничений слать сообщения AI-Мастеру, из-за чего:
1. Терялась синхронность партии (один активный игрок мог написать 3 действия подряд, пока остальные читали или формулировали свои заявки).
2. Игроки не видели намерения друг друга до того, как Мастер уже ответил.
3. Происходил лишний расход токенов LLM на каждое единичное действие вместо связного батчинга всего раунда партии.

---

## 2. Цели и ключевые требования

1. **Каждый игрок управляет строго своим персонажем:** заявка привязывается к снапшоту выбранного персонажа в комнате.
2. **Синхронный раунд отряда (Party Turn):** пока все активные участники отряда не отправят свои заявки, ИИ-Мастер не генерирует реакцию мира.
3. **Публичность заявок внутри раунда:** все игроки в реальном времени видят, кто уже готов и что именно заявил сопартиец («Торин: Ищу скрытые двери», «Элиас: Готовлю лук»).
4. **Принцип «Сказанного не вернёшь»:** после нажатия кнопки «Отправить ход» заявка блокируется от редактирования для исключения метагейминга и подгонки действий под чужие фразы.
5. **Авто-старт при 100% готовности (Вариант А):** как только последний игрок нажимает «Отправить», сервер автоматически объединяет заявки через `bundleTurnInputs` и запускает генерацию реакции мира.
6. **Кнопка принудительного хода у ДМа (Force Resolve):** если кто-то из игроков задерживается или ушёл AFK, ведущий стола (хост) может нажать «Отправить сейчас». Не успевшие игроки автоматически получают защитную стойку («Держит оборону и прикрывает отряд»).

## 4. Спецификация API и сервисов

### 4.1. `POST /api/room/[code]/turn`
- **Тело запроса:** `{ actionText: string }`
- **Авторизация:** Bearer-токен пользователя Supabase.
- **Логика:**
  1. Найти комнату по `code`.
  2. Найти участника `participant` с `characterSnapshot`.
  3. Проверить активный раунд:
     - Если пользователь уже присутствует в `activeTurn.playerInputs`, вернуть `400 Bad Request ("Заявка на этот раунд уже отправлена")`.
  4. Сохранить `PlayerTurnInput` в `player_inputs`.
  5. Вызвать `calculateTurnReadiness(room.participants, updatedInputs)`.
  6. **Если `isAllReady === true`:**
     - Сервер вызывает внутренний метод резолвинга хода (аналогично `/turn/resolve`), передавая собранный батч промпта Мастеру.
     - Ответ сохраняется, раунд закрывается, создаётся следующий раунд.
     - Ответ клиенту: `{ success: true, resolved: true, roundNumber: activeTurn.roundNumber, nextRoundNumber: activeTurn.roundNumber + 1 }`.
  7. **Если не все готовы:**
     - Ответ клиенту: `{ success: true, resolved: false, turn: updatedTurn }`.

### 4.2. `POST /api/room/[code]/turn/resolve`
- **Назначение:** Принудительное завершение хода Ведущим стола (ДМом).
- **Права:** Только `room.hostUserId === user.id`.
- **Логика:**
  1. Вычисляет список игроков с персонажами, не сдавших заявки (`pendingUserIds`).
  2. Формирует для них список `afkCharacters` с пометкой `[В ожидании/защитная стойка]`.
  3. Вызывает AI-генерацию реакции мира, закрывает раунд и открывает следующий раунд `N+1`.

### 4.3. `GET /api/room/[code]/turn`
- **Назначение:** Возвращает текущее состояние активного раунда.
- **Ответ:**
  ```json
  {
    "turn": {
      "id": "uuid",
      "roomId": "uuid",
      "roundNumber": 2,
      "status": "waiting",
      "playerInputs": {
        "user_1": {
          "userId": "user_1",
          "characterName": "Торин",
          "className": "Воин",
          "level": 1,
          "actionText": "Выбиваю дверь щитом",
          "submittedAt": 1727164800000
        }
      }
    }
  }
  ```

## 5. Компоненты пользовательского интерфейса (Frontend)

### 5.1. `PartyTurnBar` (`src/components/room/PartyTurnBar.tsx`)
Компактный светлый виджет, располагающийся над полем ввода:
1. **Строка статуса:** `⚔️ Раунд {roundNumber} • Готовность отряда: {readyCount} из {totalCount}`.
2. **Сетка карточек героев отряда:**
   - Аватар, имя героя, класс.
   - Если сдал заявку: зелёный бейдж `Готов` и блок с цитатой действия: `«Выбиваю дверь щитом»`.
   - Если думает: жёлтый/серый бейдж `Обдумывает...` со спокойным пульсирующим индикатором.
3. **Статус генерации Мастера:**
   - Если раунд в процессе генерации (`status === "resolving"` или отправлен запрос):
     `✨ Мастер описывает последствия действий отряда...` (со спиннером `Loader2`).
4. **Кнопка для Ведущего:**
   - Если текущий пользователь хост и `readyCount > 0 && readyCount < totalCount`:
     Кнопка `⚡ Отправить ход сейчас (пропустить ожидающих)`.

### 5.2. Интеграция в `DnDApp.tsx`
1. **Стейт активного раунда:**
   - `const [activeRoomTurn, setActiveRoomTurn] = useState<RoomTurn | null>(null);`
   - `const [submittingTurn, setSubmittingTurn] = useState(false);`
   - `const [resolvingTurn, setResolvingTurn] = useState(false);`
2. **Синхронизация раунда:**
   - В существующий цикл поллинга сетевой комнаты (раз в 3 сек) добавляется запрос `GET /api/room/[code]/turn`.
3. **Обработка отправки формы:**
   - Если `activeRoom && activeCampaign`:
     - Перехват `handleSubmit`: вместо прямого вызова одиночного `sendMessage` отправляется `POST /api/room/[code]/turn` с `{ actionText: input }`.
     - Инпут очищается, блокируется с сообщением «Заявка на раунд {roundNumber} отправлена».
   - Если одиночный режим (нет комнаты):
     - Работает прежний режим одиночного диалога с AI-Мастером.
