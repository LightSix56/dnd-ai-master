# Версии персонажа для кампаний и единый лист для двух сайтов

Дата: 2026-10-05. Статус: согласовано.

Затрагивает два проекта: `dnd-ai-master` (сайт мастера) и `dnd5e-character-sheet` (сайт листа).
Оба развёрнуты на Vercel и работают с одной базой Supabase.

## Зачем

Сейчас при входе в комнату сайт мастера один раз копирует лист персонажа к себе и дальше
живёт с этой копией. Отсюда три проблемы:

- изменения на сайте листа (прокачка, снаряжение) в кампанию не попадают;
- копий несколько (снимок у участника комнаты, лист в `Character.notes`, строка в `characters`),
  они расходятся — так появлялись атаки `+14` и «пустые» герои со всеми десятками;
- один персонаж в двух кампаниях получил бы два разных уровня без способа их различить.

## Что должно получиться

1. Для каждой кампании у персонажа своя отдельная копия. Оригинал и копии для других
   кампаний не меняются.
2. Эту копию видно на сайте листа, её можно открыть и прокачать.
3. Прокачать уровень копии можно, только когда хватает опыта.
4. После прокачки игроки сообщают мастеру, что партия прокачалась, и память мастера обновляется.
5. У листа один источник правды — строка в базе (`characters.data`, JSON). Сайт мастера
   читает её напрямую. Снимков листа нет нигде: ни у участника комнаты, ни в базе
   кампании, ни как запасного пути.

Что не входит: исправление причины битых `+14` в сохранённом поле `attacks` на сайте листа
(мастер это поле уже не использует), перенос персонажа между кампаниями, слияние версии
обратно в оригинал.

## Как устроено сейчас

- Таблица `public.characters` (Supabase): `id`, `user_id`, `name`, `data` (весь лист, JSON),
  `portrait_url`, `created_at`, `updated_at`. Её создаёт и редактирует сайт листа
  (`src/app/api/characters/route.ts`), читать и менять можно только свои строки.
- Сайт мастера читает её в `/api/room/user-characters` (вкладка «Мои персонажи»).
- `RoomService.joinRoom` при входе: пишет снимок в `room_participants.character_snapshot`,
  копирует лист в `Character.notes` базы кампании и перезаписывает строку в `characters`.
- Лист из `Character.notes` разбирают `sheetFromNotes` / `unwrapSheet` — для окна d20,
  боя (`character-adapter.ts`), досье мастера (`frozen-prefix.ts`), карточки героя.
- Опыт начисляет скрипт `awardCombatVictoryXP` в базу кампании (не в лист).
- На сайте листа опыт — просто поле ввода; прокачка опытом не ограничена.

## Решение

### 1. Версия кампании — строка в `characters`

В `public.characters` добавляются колонки:

| Колонка | Тип | Смысл |
|---|---|---|
| `source_character_id` | uuid, null | оригинал, с которого сделана версия |
| `campaign_id` | text, null | кампания, для которой версия |
| `campaign_name` | text, null | название кампании для показа на сайте листа |
| `revision` | integer, по умолчанию 0 | счётчик изменений строки |

Строка без `campaign_id` — оригинал. Уникальность: одна версия на пару
(`source_character_id`, `campaign_id`). `source_character_id` при удалении оригинала
обнуляется (версия остаётся — партия не должна потерять героя).

Имя версии: «Токсин (Встреча)». Поле `data.name` внутри листа остаётся «Токсин» — в игре
герой называется по-прежнему.

`revision` увеличивает триггер базы при каждом изменении строки, а не приложение.

### 2. Вход в комнату

Игрок выбирает оригинал. Сервер мастера:

1. проверяет, что оригинал принадлежит игроку;
2. ищет версию для этой кампании; если её нет — создаёт копированием `data` и портрета;
3. записывает участнику комнаты `character_id` версии.

Если игрок выбрал уже существующую версию этой кампании — берётся она. Версию чужой
кампании выбрать нельзя. В оригинал сайт мастера не пишет никогда.

«Герои кампании» и «Создать нового» (быстрое создание в комнате) тоже создают строку
в `characters` сразу как версию этой кампании, без оригинала.

Комната без кампании (лобби до старта): версия создаётся в момент, когда у комнаты
появляется кампания; до этого участник привязан к оригиналу только на чтение.

### 3. Чтение листа сайтом мастера

Один модуль `src/lib/dnd/sheet-store.ts`:

- `loadSheet(characterId)` — лист из `characters.data` плюс `revision`;
- `loadPartySheets(campaignId)` — листы всех участников кампании одним запросом;
- без долгого хранения: в пределах одного запроса лист читается один раз, между запросами
  не кэшируется.

Все потребители переходят на него: окно d20 (`d20-helper.ts`), бой
(`character-adapter.ts`), досье мастера (`frozen-prefix.ts`), карточка героя, выбор героя.
`room_participants.character_snapshot` и лист в `Character.notes` больше не пишутся и не
читаются; колонка `character_snapshot` и код разбора листа из заметок (`sheetFromNotes`,
`unwrapSheet` для заметок) удаляются.

Строка `Character` в базе кампании остаётся как привязка героя к кампании и хранит то,
что относится к игре, а не к листу (тип, статус, заметки мастера). Она получает поле
`sheetCharacterId` — ссылку на версию.

### 4. Бой

При создании боя участники боя строятся из листа в базе. Дальше бой ведёт свои рабочие
числа (хиты, потраченные ячейки, состояния) — это состояние боя, а не копия листа.
Пока бой идёт, изменения на сайте листа в него не попадают. Когда бой завершён, сервер записывает в версию только игровые поля:
текущие хиты, потраченные ячейки заклинаний, состояния и опыт.

Запись точечная (обновляются отдельные поля JSON в базе), а не замена всего листа.

### 5. Опыт и прокачка

`awardCombatVictoryXP` начисляет опыт в `data.experiencePoints` версии.

На сайте листа для версии кампании кнопка повышения уровня доступна, только когда опыта
хватает на следующий уровень по таблице D&D 5e (300, 900, 2 700, 6 500 …). Рядом
показано, сколько опыта не хватает. Для оригиналов без кампании всё остаётся как сейчас —
без ограничений.

Долгий отдых выполняет игрок на сайте листа (окно отдыха уже есть). Мастер только
сообщает, что отдых возможен.

### 6. «Партия прокачалась»

Сервер мастера помнит, с какими `revision` листов собрано досье мастера. Если у кого-то
из партии версия изменилась и боя нет, в чате появляется кнопка «Партия прокачалась».
По нажатию:

1. досье мастера пересобирается из свежих листов (кэш контекста сбрасывается);
2. в историю кампании добавляется системное сообщение для мастера:
   «Партия прокачала уровень, посмотри их листы заново», с перечнем, кто на каком уровне;
3. все игроки комнаты видят в чате отметку об обновлении.

Нажать может любой участник. Во время боя кнопка недоступна.

Окно d20 и карточка героя читают лист напрямую и свежие данные показывают сразу, без
кнопки. Кнопка нужна именно для памяти мастера.

### 7. Сайт листа

- В списке персонажей версии показаны под своим оригиналом с подписью кампании.
- Версию можно открыть, редактировать и прокачивать как обычного персонажа.
- Сохранение передаёт `revision`, с которой лист был загружен. Если в базе она уже
  другая (мастер записал итоги боя), сохранение не затирает данные: сайт подгружает
  свежие игровые поля (хиты, ячейки, состояния, опыт), накладывает на них правки игрока
  и сохраняет снова.
- Удаление версии, которая участвует в незакрытой комнате, запрещено с понятным
  сообщением.

### 8. Миграция существующих данных

Одноразовый скрипт для уже идущих кампаний: для каждого героя игрока берётся лист из
`Character.notes`; если у участника есть строка в `characters`, она становится оригиналом,
а для кампании создаётся версия; привязки участников и `Character.sheetCharacterId`
обновляются. Скрипт можно запускать повторно.

Старые данные (`character_snapshot`, лист в `notes`) нужны только этому скрипту как
исходник. После миграции они нигде не читаются: запасного пути через снимок нет.
Колонка и старый код удаляются на последнем этапе.

## Ошибки и крайние случаи

- Версия не найдена (удалена вручную): герой показывается с пометкой «лист недоступен»,
  игроку предлагается выбрать персонажа заново. Бой для такого героя не запускается.
- База недоступна при чтении листа: действие, которому нужен лист (бросок, старт боя),
  не выполняется и показывает ошибку с предложением повторить. Устаревшие данные
  не подставляются.
- Запись итогов боя не удалась: повтор; если не вышло — итоги остаются в базе кампании
  и записываются при следующем обращении к герою.
- Игрок в двух кампаниях одним оригиналом: две независимые версии.
- Гость без аккаунта: версия создаётся под гостевым пользователем, как сейчас.

## Права доступа

Правила чтения и записи `characters` для владельца не меняются. Сайт мастера работает
сервисным ключом и перед каждым действием сам проверяет, что запрашивающий — владелец
персонажа или участник той же кампании (`campaign-access.ts`). Листы других игроков
в браузер отдаются только участникам той же комнаты.

## Проверка

- Модульные тесты: создание и поиск версии, запрет чужих версий, `loadSheet`, точечная
  запись итогов боя, порог опыта, определение «лист изменился», слияние при конфликте
  ревизий.
- Тест миграции на копии данных.
- Вручную на превью обоих сайтов: вход двумя игроками, бой, начисление опыта, прокачка
  на сайте листа, кнопка «Партия прокачалась», проверка, что оригинал не изменился.

## Порядок выпуска

Каждый этап — сначала ветка `dev` и превью, после проверки — `main`.

1. База: новые колонки и триггер ревизии (только добавление, старый код работает).
2. Сайт листа: версии в списке, сохранение с ревизией, порог опыта.
3. Сайт мастера: создание версий, `sheet-store`, перевод потребителей.
4. Сайт мастера: запись итогов боя и опыта в версию.
5. Сайт мастера: кнопка «Партия прокачалась».
6. Миграция старых героев, затем удаление старого кода и полей.
